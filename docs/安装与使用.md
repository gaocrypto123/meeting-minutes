# meeting-minutes · 会议纪要技能

把一场会议的录音 / 转写稿 / 文字记录，变成**可以直接发出去**的纪要 Word、汇报 PPT、图文摘要和待确认清单。

和普通"帮我写个会议纪要"的区别只有一句话：

> **纪要里每一条"共识""决策""行动项"，都必须能在原话里找到依据。找不到就写"待确认"，不猜。**

---

## 一、三步装上

### 第 1 步：放文件

把整个 `meeting-minutes` 文件夹复制到你的技能目录：

| 环境 | 路径 |
|---|---|
| WorkBuddy（Windows） | `C:\Users\<你的用户名>\.workbuddy\skills\` |
| WorkBuddy（macOS / Linux） | `~/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` 或 `项目/.claude/skills/` |

装完应该是这样：

```
skills/
└── meeting-minutes/
    ├── SKILL.md                 ← 主流程
    ├── references/
    │   ├── templates.md         ← 四套章节模板
    │   ├── evidence-and-qc.md   ← 证据字段 + 质检规范
    │   └── output-formats.md    ← Word / PPT 版式规范
    └── scripts/
        ├── init_meeting_workspace.py
        ├── doctor.py            ← 环境体检（先跑它）
        ├── transcribe.py        ← 本地离线转写
        ├── make_manual_template.py  ← 人工补录模板
        ├── append_checkpoint.py
        └── qc_check.py
```

### 第 2 步：确认 Python

需要 Python 3.9+。跑转写时会自动装 `av` / `numpy` / `faster-whisper`（腾讯云源），**不用手动装**。

```bash
python --version
```

### 第 3 步：说一句话就能用

```
用 meeting-minutes 技能，帮我把这段录音整理成会议纪要
```

## 二、转写这件事：三条路，先判档再动手

**转写不是必经步骤，只是拿稿方式之一。** 这是本技能第二版最大的改动 —— 之前把转写当成硬前置，结果很多人卡在这一步就走不下去了。

### 先判档

| 档位 | 你的输入 | 走哪条路 |
|---|---|---|
| **甲** | 已有文字稿（转写稿 / 会议速记 / 聊天记录 / 字幕） | **路 1** —— 永远不要碰转写脚本 |
| **乙** | 只有录音，且体检说能转 | **路 2** —— 本地离线转写 |
| **丙** | 只有录音，体检说不能转，或下载失败 | **路 3** —— 转人工供稿 |

### 路 1 · 直接用现成文字稿（甲档）

把文字整理成 `01-转写稿.md` 就行，从 Phase 2 开始跑。**没有录音不等于纪要质量差** —— 人工速记和会议平台导出的稿子，通常比离线转写更准。

### 路 2 · 本地离线转写（乙档）

**先体检，别上来就下载**（体检 10 秒，盲试一轮 10 分钟起）：

```bash
python scripts/doctor.py --size medium
```

它会明确告诉你走哪条路：

| 结论 | 含义 | 怎么办 |
|---|---|---|
| 路径 A | 依赖齐 + 本地有模型 | 直接跑 transcribe.py |
| 路径 B | 网络通，需下载模型 | 跑 transcribe.py，自动下载（断点续传） |
| 路径 C | 本机不具备转写条件 | **立刻转路 3，不要重试** |

能转的话：

```bash
# 1) 先试跑前 60 秒确认音质
python scripts/transcribe.py "录音.m4a" --out "01-转写稿.md" --limit 60

# 2) 可用再跑全量
python scripts/transcribe.py "录音.m4a" --out "01-转写稿.md"
```

全程本地，音频不出本机，不需要 API Key。

### 路 3 · 转人工供稿（丙档）

**判定不可用后立刻停止一切转写尝试。** 三条拿稿通道，按推荐顺序：

1. **会议平台自带纪要** —— 腾讯会议 / 飞书妙记 / 钉钉闪记都自带「转写 + 自动纪要」，录完导出即可。准确率高于本地离线转写，**最省事**。
2. **手机录音机自带转写** —— iPhone 备忘录录音、小米/华为/OPPO 录音机多有「转文字」。
3. **剪映 / 讯飞听见 / 网易见外** —— 导入音频导出字幕，多数有免费额度。

实在拿不到稿子，生成一份模板边听边填：

```bash
python scripts/make_manual_template.py "录音.m4a" --out "01-转写稿.md"
```

### 三条死规矩

| # | 规矩 | 为什么 |
|---|---|---|
| T1 | **转写最多试一次**：一次体检 + 一次下载，失败立刻转路 3 | 换着花样重试每次都是十分钟级消耗，成功率还极低 |
| T2 | **禁止用浏览器自动化蹭在线转写网站** | 要登录/验证码/付费，成功率接近零，却能耗掉十几轮对话 |
| T3 | **不许说"我再试试别的办法"** | 说了就是没决策。要么给明确结论，要么转路 3 把通道交给用户 |

## 三、它怎么工作（六个阶段，每阶段留一条记录）

| 阶段 | 干什么 | 产出 |
|---|---|---|
| Phase 0 | 问清会议类型、输出形态、参会人，建工作目录 | `meta.md` |
| Phase 1 | **取得文字稿**（上面三条路选一条） | `01-转写稿.md` |
| Phase 2 | 按议题切段，逐段提炼要点，**提炼完清掉原文** | `02-要点.md` |
| Phase 3 | 全局去重，套章节模板，挂证据字段，出稿 | `03-纪要初稿.md` |
| Phase 4 | 跑质检脚本（只查不补） | `04-质检报告.md` |
| Phase 5 | 事实复核 → 出 Word / PPT / 待确认清单 / 图文摘要 | 四份交付物 |

全程每一步都写进 `checkpoints.md`，只追加不涂改 —— 中断了能续跑，事后能审计。

## 四、四套章节模板（自动按会议类型选）

| 类型 | 什么时候用 | 章节 |
|---|---|---|
| **内部工作会** | 周会、例会、进展同步 | 会议背景 / 进展同步 / 问题与阻塞 / 意见总结 / 行动项与下周计划 |
| **决策评审会** | 评审、立项、拍板 | 会议背景与评审对象 / 评审意见 / 决策结论 / 行动项 / 待确认与风险 |
| **跨部门对接会** | 多方协同、接口拉通 | 会议背景 / 议题与讨论要点 / 意见总结 / 行动项 / 待确认与风险 |
| **外部沟通会** | 客户、供应商、洽谈 | 会议背景 / 客户需求与反馈 / 我方回应与承诺 / 行动项（分我方/对方）/ 待确认与风险 |

判定不出类型时，技能会**问你**，不猜 —— 选错骨架等于全篇返工。

每套 5 章。**章节标题不能删**，本次不涉及就写"本次不适用"。
需求、共识、决策、技术要点**统一收进"意见总结"一章**，不拆到多章来回讲。

## 五、五条铁律（违反会导致质检不通过）

| # | 铁律 |
|---|---|
| R1 | 共识 / 方案 / 决策 / 行动项 / 技术要点必须有原文出处。找不到 → 写"待确认" |
| R2 | 模板章节标题不得删除，不适用写"本次不适用" |
| R3 | 行动项必须有 责任人 + 交付物 + 截止日。缺失写"待确认"，**不得编造** |
| R4 | 不出现原文中不存在的数字、日期、人名、承诺。听不清标 `[?]`，**不猜** |
| R5 | 同一件事只在"意见总结"说一次，不跨章重复 |

**待确认不是瑕疵，是交付价值。** 一份诚实标了 8 条待确认的纪要，比一份看起来很完整但全是编的纪要值钱得多。

## 六、交付物

| 文件 | 用途 |
|---|---|
| `会议纪要.docx` | 正式归档版，文末附决策清单 + 行动项清单 |
| `会议汇报.pptx` | 8-12 页汇报版，一页一观点 |
| `图文摘要.md` | 卡片版，直接贴群 / 贴邮件 |
| `待确认清单.md` | 所有存疑项汇总，附建议确认对象 |

Word 和 PPT **都从通过质检的初稿派生**，不从要点稿派生 —— 否则会绕过证据校验。

## 七、常见问题

**Q：没有录音，只有文字记录怎么办？**
直接把文字粘给 AI，从 Phase 2 开始跑，跳过转写。这是质量最高的一条路。

**Q：模型下载不动 / 连不上下载源怎么办？**
先跑 `doctor.py` 确认到底哪一步不通。若确认是网络问题，两个选择：
- 换小档位试：`--model base`（138 MiB，只有 medium 的十分之一，近场录音够用）
- 手动下载：脚本失败时会打印 4 个直链和目标目录，用浏览器或迅雷下完放进去，加 `--model-dir` 指定即可

**都不行就转路 3**，别死磕 —— 会议平台自带纪要往往比你折腾本地转写更快。

**Q：转写要多久？要不要联网上传？**
不上传，全程本地。CPU 上 medium 模型约 1.9 倍实时 —— 18 分钟音频约 10 分钟。首次运行需下载模型（medium 约 1.4 GB），之后离线可用。

**Q：为什么责任人全是"待确认"？**
因为**没有做说话人分离**，分不清谁在说话。要真实责任人，把参会人名单给 AI，让它在 Phase 5 回填。

**Q：质检 FAIL 了怎么办？**
只有两个合法动作：**标注"待确认"**，或者**删除该条目**。禁止为了让质检通过而补写原文没有的内容 —— 尤其禁止编造行号，那会让整份纪要失去可复核性。

**Q：录音质量很差怎么办？**
手机远距离录制、多人抢话的音频，转写准确率会明显下降。技能会把失效区间单列出来，不混进正文。建议：录音设备放近一点，比换任何模型都管用。

**Q：能改模板吗？**
能。改 `references/templates.md` 即可。但注意 `scripts/qc_check.py` 靠 `## 1. 标题` 这个格式认章节，改标题格式会让质检失效。

## 八、手动跑脚本（AI 一般会自动跑，这列供排查用）

```bash
# Phase 1 先体检（退出码 0=可转写，3=不可用转路 3）
python scripts/doctor.py --size medium --json doctor.json

# Phase 0 建工作目录
python scripts/init_meeting_workspace.py "会议名" --dir "<输出根目录>" \
    --type 内部工作会 --date 2026-09-18 --location "3F会议室A" \
    --attendees "张三(主持),李四" --output both

# Phase 1 转写（先试跑 60 秒，再跑全量；中断加 --resume 续跑）
python scripts/transcribe.py "<音频路径>" --out "<工作目录>/01-转写稿.md" --limit 60
python scripts/transcribe.py "<音频路径>" --out "<工作目录>/01-转写稿.md"

# Phase 1 路 3：人工补录模板
python scripts/make_manual_template.py "<音频路径>" --out "<工作目录>/01-转写稿.md"

# 每阶段末追加节点记录
python scripts/append_checkpoint.py "<工作目录>" --id CP1 \
    --phase "Phase 1 取得文字稿" --output "01-转写稿.md" \
    --basis "本地 medium 模型" --status 完成 \
    --pending "待补参会人" --next "CP2 切段提炼"

# Phase 4 质检（退出码 0=PASS/INCOMPLETE，1=FAIL）
python scripts/qc_check.py "<工作目录>/03-纪要初稿.md" \
    --transcript "<工作目录>/01-转写稿.md" \
    --template 内部工作会 \
    --out "<工作目录>/04-质检报告.md"
```
