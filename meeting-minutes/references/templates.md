# 章节模板（Phase 3 用）

## 一、通用规则（四套模板共用）

1. **标题不删**：模板里出现的章节标题必须原样保留。本次会议不涉及 → 正文写"本次不适用"。
2. **背景压 3 句**：`会议背景` 最多 3 句话，写完直奔议题。
3. **每套不超过 5 章**。要加内容，往这 5 章里加，不新开章。
4. **动态编号**：过滤掉"本次不适用"的章节后，剩余章节按 1、2、3… 重排。
   允许整章删除的**唯二**情况：
   - (a) 该章不在本次会议类型的模板里；
   - (b) 整章无内容且全篇讨论中无任何痕迹（说明确实是空议题）。
   其余一律保留标题 + 写"本次不适用"。
5. **意见总结是唯一收口**：需求、共识、决策、技术要点全部进 `意见总结`，禁止拆到"议题讨论""结论""决定"等多个章节来回讲。
6. **行动项独立成章**，不写在正文段落里，保证能被质检脚本抓到。
7. 每条要点必须挂证据字段，格式见 `references/evidence-and-qc.md`。

## 二、会议类型判定

| 类型 | 判定关键词 | 特征 |
|---|---|---|
| 跨部门对接会 | 对接、协同、配合、双方、接口、流程拉通、上游/下游 | 有多方分工，需要明确交接与责任边界 |
| 内部工作会 | 周会、例会、站会、进展、同步、内部、组内 | 以进度同步和阻塞清理为主 |
| 决策评审会 | 评审、立项、评审会、方案过会、是否通过、拍板 | 有明确评审对象与通过/否决结论 |
| 外部沟通会 | 客户、甲方、乙方、供应商、外部、来访、洽谈 | 有对外承诺，需区分我方/对方行动项 |

判定不出 → **问用户**，不要猜。会议类型决定骨架，猜错等于全篇返工。

## 三、四套模板

### A. 跨部门对接会（5 章）

```markdown
## 1. 会议背景
（≤3 句：为什么开、谁发起、要解决什么）

## 2. 议题与讨论要点
### 议题1 · <议题名>（时间区间）
- <发言要点>   出处：…
### 议题2 · …

## 3. 意见总结
### 3.1 需求
### 3.2 共识
### 3.3 决策
### 3.4 技术要点

## 4. 行动项
（每条独立成条，含责任人/交付物/截止日/状态/出处）

## 5. 待确认与风险
```

### B. 内部工作会（5 章）

```markdown
## 1. 会议背景
## 2. 进展同步
### 2.1 <成员/模块> 进展
## 3. 问题与阻塞
## 4. 意见总结
### 4.1 决策
### 4.2 待定事项
### 4.3 技术要点
## 5. 行动项与下周计划
```

### C. 决策评审会（5 章）

```markdown
## 1. 会议背景与评审对象
## 2. 评审意见
### 2.1 <评审人> 意见
## 3. 决策结论
（每条决策须含：结论 / 依据 / 状态 / 出处；否决项也要写，注明"已否决"）
## 4. 行动项
## 5. 待确认与风险
```

### D. 外部沟通会（5 章）

```markdown
## 1. 会议背景
## 2. 客户需求与反馈
## 3. 我方回应与承诺
（对外承诺须逐字引用我方原话，不得替对方加码）
## 4. 行动项
### 4.1 我方行动项
### 4.2 对方行动项
## 5. 待确认与风险
```

## 四、信息归集映射（出稿时按这张表分流）

| 信息类型 | 唯一归属章节 | 不得出现的位置 |
|---|---|---|
| 需求 | 意见总结 · 需求 | 议题讨论、行动项 |
| 共识 | 意见总结 · 共识 | 决策结论 |
| 决策 / 结论 | 意见总结 · 决策（模板 C 为 决策结论） | 议题讨论 |
| 技术要点 | 意见总结 · 技术要点 | 进展同步 |
| 行动项 / 待办 | 行动项（独立章节） | 意见总结、议题讨论 |
| 未解决问题 / 阻塞 | 待确认与风险（模板 B 为 问题与阻塞） | 意见总结 |
| 风险 | 待确认与风险 | 议题讨论 |

**同一条信息只能出现在一个章节。** 去重时若发现同一事项在两处出现，保留归属表指定的那处。

## 五、动态编号示例

模板 A 原始 5 章，本次会议不涉及"待确认与风险"（无风险、无待确认项）：

```markdown
## 1. 会议背景
## 2. 议题与讨论要点
## 3. 意见总结
## 4. 行动项
## 5. 待确认与风险

本次不适用。（本次会议未产生风险与待确认事项）
```

标题保留、写"本次不适用"、**不重排编号** —— 因为该章仍在模板内。
只有当整章被合法删除（见通用规则 4 的 a/b 两种情形）时，后面的章节才上移重排。

## 六、章节命名硬约束

- 一级章节用 `## 1. 标题`；二级用 `### 1.1 标题`。质检脚本靠这个格式认章节，格式不能改。
- 章节标题内不出现标点以外的修饰（不写"## 1. 会议背景（很重要）"）。
