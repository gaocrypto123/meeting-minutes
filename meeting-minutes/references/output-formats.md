# 交付物格式规范（v2）

所有交付物都从 `纪要/会议纪要.md`（已通过质检）派生，**不要从要点稿直接生成**。

## 一、交付物清单与触发条件

| 交付物 | 何时产出 | 由谁生成 |
|---|---|---|
| `会议纪要.html` | **总是产出** | `build_outputs.py` |
| `会议纪要.docx` | 用户在开工确认单里选了 Word | `build_outputs.py` |
| `图文摘要.md` / `.html` | 用户选了图文摘要 | 手写 + `build_outputs.py` |
| `待确认清单.md` / `.html` | **总是产出** | 手写 + `build_outputs.py` |
| `会议汇报.pptx` | **只有用户明确要 PPT 时才做** | `python-pptx` 或 `tencent-pptx` |

**v1 的教训**：v1 默认"两版都给"，结果用户既没要求也没准备。v2 把 PPT 改成显式触发，并在开工确认单里问清楚。

## 二、HTML 版（默认可读版）

- 双击即可用浏览器打开，不需要装任何东西
- 顶部自动生成**目录**，点标题可跳转
- 每条结论渲染成**卡片**：类型色标 + 结论 + 证据条 + 引文块
- 纪要里的 `[时:分:秒]` 是链接，点击跳回 `原文/转写稿.html` 对应那一句
- H1 之后、第一个 `##` 之前的内容渲染成**速览高亮块**

## 三、Word 版

- A4，正文微软雅黑 10.5pt，行距 1.5
- 主色蓝莫兰迪 `#5B7C99`（标题、表头、类型色标）
- 每条结论：类型色标段落（左侧竖线）+ 结论加粗 + 灰色小字证据条 + 斜体引文块
- 表格用 `Table Grid`，表头主色
- 状态色标：已确认/已决策 蓝 `#5B7C99`；待确认 灰 `#8A8F98`；风险/已否决 暗红 `#B4646B`；已延期 暗金 `#A08A63`

**读者只看表格和色标就能掌握全部结论与待办**，正文是给需要上下文的人看的。

## 四、Markdown 母版的排版硬要求

渲染器依赖这些约定，写的时候就要照着来：

```markdown
# 会议纪要 · <会议名>          ← H1

| 会议 | 日期 | 时长 | 参会人 | 有效讨论区间 |   ← 速览（第一个 ## 之前）
**这次要解决什么** …
**结论概览** …
**最需要你确认的 3 件事** …

## 1. 会议背景                  ← 一级章节
### 4.1 需求与共识              ← 二级子节
- **需求 R1**：一句话结论        ← 条目
  - 状态：已确认                 ← 字段（缩进 2 空格）
  - 出处：[00:03:37]
  - 引用：「…」

## 附录 · 非议题内容（保留备查）  ← 附录，不参与模板校验
```

## 五、PPT 页序（要做时才用，8–12 页）

| 页 | 内容 |
|---|---|
| 1 | 封面：会议名 / 时间 / 地点 / 参会人 |
| 2 | 会议背景与目标（≤3 条） |
| 3 | 核心结论速览（≤5 条，带状态色标） |
| 4–6 | 议题要点（一议题一页，每页 ≤4 条） |
| 7 | 决策清单 |
| 8 | 行动项 |
| 9 | 待确认与风险 |
| 10 | 附录：术语 / 数据来源（可省） |

页数不够不要硬凑；"待确认"必须保留在 PPT 里，那不是要藏起来的东西。

## 六、命名与落盘

```
<会议名>_<日期>/
├── 原文/   转写稿.md / .json / .html
├── 纪要/   会议纪要.md / .docx / .html、图文摘要、待确认清单、出处校验报告
└── 过程/   meta.md、checkpoints.md、要点.md、质检报告.md
```

- 文件名固定，重复生成覆盖同名文件；**不要**建 `会议纪要_v2.docx`（版本靠 `checkpoints.md` 追溯）
- 原文目录只读，任何情况下不手改

## 七、常见坑

- **PPT 塞满正文** → 汇报版不是纪要的缩小版，细节指向 Word
- **Word 里掉了出处** → 出处的意义就是让人能复核
- **两版数字不一致** → 说明有人手改了，回退重出
- **把「待确认」从任何一版里删掉** → 那是交付价值，不是瑕疵
- **忘了 html** → 群里转发和快速查阅用的就是 html
