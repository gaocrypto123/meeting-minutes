# meeting-minutes-v2 使用说明

把一场会议的录音，变成**可以直接发出去、而且每条结论都能被机器验证**的会议纪要。

和"让 AI 直接写篇纪要"的区别只有一句话：

> **纪要里每一条共识、决策、行动项，都必须能在原话里找到依据。找不到就写「待确认」，不猜。**

---

## 一、它在哪里

| 东西 | 位置 | 体积 |
|---|---|---|
| 技能包（代码 + 说明） | 你解压出来的那个文件夹 | 几十 KB |
| 重资产（Python 环境 + 模型） | 默认 `%USERPROFILE%\.meeting-minutes`，安装时可以改到别的盘 | 约 1–2.5 GB |

**想彻底删掉**：把上面那个重资产目录整个删掉即可，电脑恢复原样。
技能包本身不改注册表、不写环境变量、不往系统目录装东西。

> 具体安装步骤见同目录的 `安装说明.md`。

---

## 二、用一句话就能跑

```
用 meeting-minutes-v2 技能，把这段录音整理成会议纪要
```

然后填写**开工确认单**（见下），我就能从建档一路做到交付。

---

## 三、开工确认单（每场会必填）

```
1. 会议类型：内部工作会 / 决策评审会 / 跨部门对接会 / 外部沟通会
2. 参会人：姓名 + 角色 + 是否发言（未发言的人不出现在正文）
3. 说话人数：几人（填了，「发言人1/2/3」才会稳定；不知道就填"不知道"）
4. 交付形态：Word 纪要 / 图文摘要 / PPT（可多选）
5. 无关段落：寒暄、吃饭、闲聊 → 保留并标记 / 直接剔除
6. 术语表：有没有经常被听错的词（可不填）
```

---

## 四、你会拿到什么

```
<会议名>_<日期>/
├── 原文/  转写稿.md（人看）、.json（机器校验用）、.html（带锚点）
├── 纪要/  会议纪要.md（母版）、.docx（Word）、.html（双击看，可点回原文）
│          图文摘要、待确认清单、出处校验报告
└── 过程/  开工确认单、节点记录、要点稿、质检报告
```

**原文和纪要分开放**，是为了你随时能核对原话，也不会在改纪要时污染原文。

---

## 五、六个阶段

| 阶段 | 干什么 | 你参与吗 |
|---|---|---|
| Phase 0 | 开工确认单 + 建目录 | **要你填** |
| Phase 1 | 先判档 → 三条路（有稿直接用 / 本地转写 / 人工供稿） | 不用 |
| Phase 2 | 按议题切段、逐段提炼、原文即弃 | 不用 |
| Phase 3 | 去重、套模板、挂时间戳锚点、出稿 | 不用 |
| Phase 4 | 六项质检 + 锚点对账 | 不用 |
| Phase 5 | 出 Word / HTML / 图文摘要，PPT 按需 | 选交付形态 |

### Phase 1 的三条路（按你给的材料自动分档）

| 档位 | 材料 | 走哪条路 |
|---|---|---|
| 甲 | 已有文字稿（速记 / 字幕 / 平台导出） | **路 1** —— 直接规范化，跳过转写 |
| 乙 | 录音，体检说能转 | **路 2** —— 本地离线转写（含说话人分离） |
| 丙 | 录音，体检说本机不行 | **路 3** —— 转人工供稿，立即停止尝试转写 |

判档靠 `python scripts/doctor.py`，体检末尾会给路线结论 A / B / C。
拿到 C 就别折腾了 —— 会议平台自带纪要（腾讯会议 / 飞书妙记 / 钉钉闪记）通常比本地转写更准，也更快。

## 六、常见问题

**Q：转写要联网吗？会上传我的录音吗？**
不联网、不上传，全程本地。模型已经装在你机器上。

**Q：本机装不上 / 连不下模型怎么办？**
先跑 `python scripts/doctor.py` 看路线结论。判定 C 就转人工供稿：
会议平台自带纪要（腾讯会议 / 飞书妙记 / 钉钉闪记）、手机录音机转文字、剪映 / 讯飞听见，
三条通道任选一条拿到文字稿，直接给 AI 从 Phase 2 开始跑。**别死磕本地转写。**

**Q：我已经有文字稿了，还要转写吗？**
不用。材料选「已有文字稿」就会跳过整个转写环节。人工速记和平台导出的稿子
通常比离线转写更准 —— 没有录音不等于纪要质量差。

**Q：转一场会要多久？**
15 分钟的录音约 10 分钟（medium 模型）。转写速度和你的 CPU 有关。

**Q：为什么责任人全是"待确认"？**
因为说话人编号只是声纹聚类，不是真实身份。你在确认单里给了姓名，才能映射成真名。

**Q：说话人编号准吗？**
在远场、多人抢话的录音里，会有 10–20% 的句子判错边界。我的处理是：能确定的标出来，
拿不准的进待确认清单，**不硬猜**。你在确认单里填人数，能明显改善。

**Q："待确认"是不是没做完？**
恰恰相反。一份诚实标了 8 条待确认的纪要，比一份看起来很完整但全是编的纪要值钱得多。

**Q：术语表怎么用？**
编辑 `meeting-minutes-v2\术语表.txt`，每行写「错的写法 = 正确写法」，比如
`PVT = PPT`。以后所有会议都会自动生效。

**Q：质检 FAIL 了怎么办？**
只有两个合法动作：标注「待确认」，或者删除该条目。**禁止为了让质检通过而补写原文没有的内容**，
尤其是编造时间戳——那会让整份纪要失去可复核性。

**Q：想换模型？**
改 `config.json` 里的 `defaults.asr_model`（`small` 快、`medium` 准）。

**Q：想多做一份 PPT？**
说一声就行，依赖已经装好（python-pptx 1.0.2）。默认不会做。
